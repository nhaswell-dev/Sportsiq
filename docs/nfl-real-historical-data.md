## Adapter contract and chronological gates

`sportsiq.providers.nfl_history.assess_history(csv_text, manifest)` translates a strict **nine-column projection** into existing `game_result` observations and calls `assess_nfl`. It does not accept an unrestricted/full provider CSV. The exact header (column order may vary, duplicates/extras may not) is:

    game_id,season,game_type,gameday,gametime,home_team,away_team,home_score,away_score

`gameday` and `gametime` mean scheduled Eastern calendar date and HH:MM, never completion or actual kickoff. Team IDs are explicit keys, not fuzzy aliases. `LA` and `LAR` are not silently interchanged. `season` is the NFL starting-year label; January/February dates belong to the prior starting year. A relabeled prior season cannot enter the target season.

The JSON manifest has exactly `schema_version` (integer 1), `analysis`, `snapshot`, `raw_sha256`, `row_evidence`, `coverage`:

- `analysis`: the unchanged 2E-B input contract. Existing sources may supply only scheduled-game and kickoff-verification records, not precomputed history/statistics. This prevents bypassing CSV validation. Per-leg identities and the common cutoff remain explicit.
- `snapshot`: 2E-B source metadata excluding `records` and `content_sha256`. Rights/reliability, immutable version, publication/revision/availability/retrieval and availability proof are validated by the existing source gate. Its source ID must not collide with context sources. In the implemented fallback, its reference must start `synthetic:` and its data kind must be synthetic.
- `raw_sha256`: SHA-256 of the exact UTF-8 CSV text bytes consumed; header, ordering and line endings are included. This binds the supplied file, not a remote archive. The adapter computes a separate normalized-record hash for 2E-B; it must not be described as a provider-signed historical hash.
- `row_evidence`: map from exact game ID to exactly `source_version`, `reference`, `started_at`, `completed_at`, `status`, `neutral_site`. Version must match the snapshot; nonblank reference and aware actual start/completion are required. No estimated duration, midnight finish, or neutral-site status is invented. Actual start must agree with the CSV's Eastern day and not precede its scheduled instant.
- `coverage`: exactly `source_version`, `as_of`, `expected_game_ids` (team -> unique list). The version must match, and `as_of` must equal the analysis cutoff. This is a fixture-declared inventory, not independently verified season completeness.

Every feature snapshot's publication, revision, availability and proof observation must be strictly before cutoff. Actual result completion must precede cutoff and not postdate the source revision. In-progress games, malformed scores, missing/naive completion evidence, wrong dates/season types, source-version conflicts and unavailable revisions are rejected. Snapshot-level failure blocks the entire adapter; individual rejected rows remain in adapter exclusions with row number, game ID and reason, not raw score payloads.

All target IDs are excluded **before score parsing**, including every leg's target. The adapter also excludes matching unordered team pair + Eastern target day, even under a disguised/reversed game ID. Duplicate game IDs quarantine all copies. January/UTC rollovers use explicit aware instants, not the host timezone. Remaining prior-game W/L/T, points for/against, home/away/neutral splits and opponent-record indicators are computed by the existing engine, not a second statistics implementation.

Each normalized row retains its CSV physical ending-line number (including skipped blank lines), original snapshot hash, source ID/version, explicit event times and evidence reference. Source timestamps remain separate from event times. Real mode is deliberately refused before any CSV values can become assessment features, even if a manifest asserts `license.status: approved`. Enabling a real source later requires a separate reviewed approval path, not changing a JSON flag.

## Completeness and reports

Per-team inventory statuses are `UNVERIFIED`, `INCOMPLETE`, or `DECLARED_SET_MATCHED`, with exact missing/unexpected IDs. Only `DECLARED_SET_MATCHED` permits target-team metrics. A mismatch for either target team withholds that leg's metrics and directional evidence and adds `history_incomplete`. Unverified opponent/context inventories disable the opponent-strength comparison. A declared match is not a claim of externally certified full-season coverage; the engine's coverage warning and `INSUFFICIENT_DATA` remain.

The synthetic file has **two invented prior games**, one for each target pair. It is intentionally a tiny test universe, not the actual 2026 schedule or season records. Its real team names include `(SYNTHETIC STATISTICS)` and its output displays `NOT ACTUAL NFL STATISTICS` and `SYNTHETIC_ONLY`. Those scores must never be copied into a real Rams/49ers assessment.

Both real selections use the common analytical cutoff `2026-10-18T19:00:00Z`. This is neither a later independent Monday decision nor a certification of the original mixed 12-leg combo cutoff. At this continuation's clock check (`2026-10-19T04:28:28Z`), the 49ers' previously documented scheduled kickoff (`2026-10-20T00:15:00Z`, October 19, 20:15 EDT) remains future; this milestone does not assert that game's actual kickoff or a settled result. The refusal report supplies no actual-start value for either game.

## Verification and remaining gates

    .venv/bin/python -m unittest discover -s tests -p 'test_*.py'

Tests cover both target identities, source rights and pre-cutoff timestamps, unavailable corrections, missing row completion, season/date consistency, target/disguised/reversed-target exclusion, duplicates, reordered rows, physical CSV line provenance, coverage mismatches, refusal of self-approved real data, strict/oversized JSON/CSV, and isolation from network/database/credential access. The committed refusal report must reproduce exactly. The initial unfinished suite failed only because this generated artifact was absent; review also found and fixed cross-season relabeling and inaccurate line numbers after blank CSV lines, with failing-then-passing regression tests.

Verification: **155 offline tests passed (131 existing + 24 historical-adapter tests)**. Both JSON and readable CLI modes were exercised for the synthetic example and real-target refusal; whitespace and staged secrets/security checks passed before commit.

Remaining real-data gates: applicable reusable-data rights/attribution; independently evidenced exact pre-cutoff snapshot bytes/publication; reliable prior-game actual completion and revision lineage; externally verified complete team/opponent inventory; and approved target schedule/actual-kickoff evidence for any claimed historical replay. No real report is generated until those gates pass. Winning probabilities, EV, betting recommendations, Kalshi price history and trading remain out of scope.
